# Multimodal resource probe (M4-10)

A separate developer-only iPhone app measures native SDK OCR, recorded-audio
recognition and speech synthesis alongside a paced idle baseline. It uses a
synthetic image and a synthesized recording; no camera, microphone, user file or
personal-data permission is requested. Measurement never requests installation.
An explicit, confirmed **Prepare English speech data** action can download system
models outside measured phases. Readiness in another app does not establish this
probe's readiness: check here before collecting a fresh run. Missing recognition
assets still produce an explicit unavailable path.

The source workload is pinned in
[`workload.json`](../../Benchmarks/MultimodalResources/workload.json). See the
[measurement protocol](../../Benchmarks/MultimodalResources/README.md) for timing,
provenance, battery exclusions and interpretation.

## Build and run

The committed project is generated by XcodeGen. Supply your signing team locally:

```bash
xcodegen generate --spec Examples/MultimodalProbe/project.yml
xcodebuild -project Examples/MultimodalProbe/MultimodalProbe.xcodeproj \
  -scheme MultimodalProbe -configuration Release -destination 'id=<device-udid>' \
  -derivedDataPath /tmp/lak-resource-probe DEVELOPMENT_TEAM=<team-id> \
  -allowProvisioningUpdates build
xcrun devicectl device install app --device <device-id> \
  /tmp/lak-resource-probe/Build/Products/Release-iphoneos/MultimodalProbe.app
```

Open MultimodalProbe and select the 60-second phases for exploratory resource
samples, or the 20-minute battery protocol (four 300-second phases). **Unplug the
phone before starting the battery protocol.** Set brightness beforehand, leave
this screen in the foreground, and avoid other device activity. The app disables
the idle timer while running and restores it and battery-monitoring state when
finished. Backgrounding or critical thermal state interrupts the run. Cancel is
available throughout preparation and measurement; native work can take time to
return from cancellation.

Preparation generates the fixed OCR image and synthesizes one known recording.
These costs are outside measured phases. Synthesis is therefore warmed; OCR/STT
first calls are retained. The synthesized audio hash and selected voice identifier
are recorded because output can vary by installed voice and OS. This is not a
speech-accuracy benchmark or evidence that an unavailable locale was exercised.

## CLI collection

A fresh UUID binds a launch to its report. `--environment-variables` takes a JSON
**string**, not a JSON file path:

```bash
xcrun devicectl device process launch --device <device-id> --terminate-existing \
  --environment-variables '{"LOCALAGENTKIT_RESOURCE_AUTORUN":"1","LOCALAGENTKIT_RESOURCE_RUN_ID":"<fresh-uuid>"}' \
  dev.localagentkit.multimodalprobe
# After the UI reports completion (unknown paths may be unavailable):
xcrun devicectl device copy from --device <device-id> \
  --domain-type appDataContainer --domain-identifier dev.localagentkit.multimodalprobe \
  --source Documents/resource-<UPPERCASE-UUID>.jsonl --destination /tmp/resource.jsonl
python3 Benchmarks/MultimodalResources/inspect.py \
  Benchmarks/MultimodalResources/workload.json /tmp/resource.jsonl /tmp/resource-summary.json \
  --expected-run-id <fresh-uuid>
```

`LOCALAGENTKIT_RESOURCE_SECONDS` can override phase duration from 1 through 300
seconds for a diagnostic run. Durations shorter than 300 seconds cannot produce
battery-eligible results. Manual runs choose their own UUID; the completed UI
shows the report filename. Existing reports are never overwritten: a repeated CLI UUID fails file creation.
The CLI UUID applies only to autorun; each manual start generates a fresh UUID. Use a new UUID
for every launch and retain raw logs. `--allow-incomplete` permits inspection of
partial/cancelled logs, which always remain ineligible for battery claims.

To run untethered, install first, disconnect the cable and start from the phone's
button. Reconnect only after completion to retrieve the file. Do not classify a
wired/charging run as a battery benchmark, even if its battery level decreased.

## Portable checks

```bash
swift test --package-path Examples/MultimodalProbe
xcrun swift-format lint --configuration .swift-format --strict --recursive \
  Examples/MultimodalProbe/Probe Examples/MultimodalProbe/App \
  Examples/MultimodalProbe/Tests Examples/MultimodalProbe/Package.swift
python3 -m unittest discover -s Scripts/tests -p 'test_multimodal_resources.py'
```

The runner uses injected work, clock, samples and output with no SDK dependency or
native assets. Five Swift functions test ordering/completion, failed/unavailable
paths, late cancellation, thermal/background interruption and plan admission.
Eight Python functions test report freshness/structure and conservative battery
classification. CI runs these without a phone. Native paths compile in the
separate iOS project and are exercised physically; they are not compiled by the
portable Swift package.

## Native cancellation acceptance (M4-09)

`NativeSpeechTests` is a separate, hosted iPhone XCTest target; portable runner
checks do not invoke it. Prepare English speech data in this app first, then leave
the connected iPhone unlocked. The test never installs assets, captures microphone
audio or exports transcript text. Missing assets or unsupported hardware produce
an explicit skip, which does not count as acceptance.

```bash
xcodebuild -project Examples/MultimodalProbe/MultimodalProbe.xcodeproj \
  -scheme MultimodalProbe -configuration Debug -destination 'id=<device-udid>' \
  -derivedDataPath /tmp/lak-native-cancellation ENABLE_TESTABILITY=YES \
  DEVELOPMENT_TEAM=<team-id> -allowProvisioningUpdates \
  -only-testing:NativeSpeechTests test
```

The test synthesizes a known recording, uses the real SDK file-transcription path,
and cancels its task at the first nonempty analyzer volatile range. An internal
observer is available only through `@testable`; public calls do not install it.
The test asserts `.cancelled`, native progress while the private file exists,
removal of its directory, return within ten seconds of progress, and a subsequent
nonempty native transcription. A thirty-second watchdog cannot satisfy the
progress assertion. The progress callback establishes accepted audio in an active
analyzer session; it is not hardware inference profiling. The ten-second bound is
an acceptance limit, not a measured worst-case guarantee for every device.
