# Embedding device probe (M3-04)

A separate, developer-only iPhone app measures locally installed English sentence
and word assets and the real SDK `NLEmbeddingProvider` default against the bundled
synthetic benchmark corpus. It reads no personal documents, calendar or contacts,
and implements no model/package download or network request. System asset behavior
remains OS-owned; this is not an OS-level traffic-capture claim. It is independent
of LocalAgentDemo and uses its own `dev.localagentkit.embeddingprobe` bundle/container.

Open the committed Xcode project, choose your development team locally, and run on
a paired iPhone. No team ID is committed. The source project is generated by XcodeGen:

```bash
xcodegen generate --spec Examples/EmbeddingProbe/project.yml
xcodebuild -project Examples/EmbeddingProbe/EmbeddingProbe.xcodeproj \
  -scheme EmbeddingProbe -destination 'id=<device-udid>' \
  -derivedDataPath /tmp/lak-device-probe-build DEVELOPMENT_TEAM=<team-id> \
  -allowProvisioningUpdates build
```

Tap “Run bundled benchmark”. Missing assets are recorded as unavailable rather than
silently replacing the forced path. Failures discard that path's partial vectors
and do not hide other paths. The SDK-default path uses the actual SDK provider;
its internal sentence/word behavior is inferred only by comparing all observed
raw vector components against the independently forced paths, not by dimension
alone. Matching this finite fixture is not proof of every future call's behavior.

The runner processes cases sequentially and checks cancellation before/after every
awaited embedding. Cancelled runs save no new report; a previous report may remain.
Successful runs atomically write `Documents/embedding-report.json`, including a
fresh run UUID, corpus hash, per-path status/timing/export and OS/thermal metadata.
The system `physicalMemoryBytes` field is total device RAM, **not process RSS or peak
memory**. Timings exclude model construction and are uncontrolled single passes;
path order, warm caches and other device activity prevent latency/energy claims.
Ordinary runs include no MLX or Core AI model. An explicit optional Core AI
parity mode accepts a separately transferred artifact; see the
[Core AI conversion/parity guide](../../Benchmarks/EmbeddingQuality/CoreAI/README.md). There is no battery measurement or SDK provider
swap, and no missing-asset simulation or asset deletion.

## CLI-run and retrieve only this app's report

An explicit automation environment runs the same bundled fixture once at launch.
Use a fresh UUID and pass it to the host inspector to reject stale output:

```bash
xcrun devicectl device install app --device <device-id> \
  /tmp/lak-device-probe-build/Build/Products/Debug-iphoneos/EmbeddingProbe.app
xcrun devicectl device process launch --device <device-id> --terminate-existing \
  --environment-variables '{"LOCALAGENTKIT_EMBEDDING_AUTORUN":"1","LOCALAGENTKIT_EMBEDDING_RUN_ID":"<fresh-uuid>"}' \
  dev.localagentkit.embeddingprobe
# After the app reports completion:
xcrun devicectl device copy from --device <device-id> \
  --domain-type appDataContainer --domain-identifier dev.localagentkit.embeddingprobe \
  --source Documents/embedding-report.json --destination /tmp/lak-device-probe-report.json
python3 Benchmarks/EmbeddingQuality/inspect_device.py \
  Benchmarks/EmbeddingQuality/corpus.json /tmp/lak-device-probe-report.json \
  /tmp/lak-device-probe-scored.json --expected-run-id <fresh-uuid>
```

The inspector checks schema, corpus hash, run identity, exact path set, complete
vector exports and dimensions. It scores only completed paths and rejects partial
exports attached to failed/unavailable statuses. SDK path matches require every
component of every document/query vector to be within absolute 1e-6; multiple
matches or no matches remain explicit rather than being guessed.

## Verified physical run, 2026-11-05

A paired wired iPhone on iOS 27.2 (24B115) ran the signed app successfully. Both
NaturalLanguage assets were present: English sentence revision 1 / 512 dimensions
and word revision 1 / 300 dimensions. Across all 24 documents and 20 queries:

| Path | Recall@3 | Full-ranking MRR | nDCG@3 |
| --- | ---: | ---: | ---: |
| Forced sentence | 0.55 | 0.4800 | 0.4446 |
| Forced word average | 0.70 | 0.6329 | 0.6077 |
| SDK default | 0.55 | 0.4800 | 0.4446 |

The SDK's vectors matched the forced sentence path across all 44 texts. **The
missing-sentence-asset fallback was not reproduced on this phone in this run.**
Do not generalize asset presence to other devices, OS versions or later asset state.
The thermal API reported raw value 1 (fair, verified in the iOS SDK NSProcessInfo.h)
at both start and end. No thermal change, battery cost or process peak memory is
inferred. Raw report hash, source provenance and scored ID-only results live under
`Benchmarks/EmbeddingQuality/results/iphone-2026-11-05`; raw vectors remain local
temporary artifacts. Device name, serial, UDID and development-team identity are
not included in the recorded results.

## Checks

```bash
swift test --package-path Examples/EmbeddingProbe
xcrun swift-format lint --configuration .swift-format --strict --recursive \
  Examples/EmbeddingProbe/Probe Examples/EmbeddingProbe/App Examples/EmbeddingProbe/Tests \
  Examples/EmbeddingProbe/Package.swift
python3 -m unittest discover -s Scripts/tests -p 'test_*.py'
```

Six runner test functions use injected mock closures, never real model assets:
complete export/round-trip, unavailable/failing path isolation, invalid vectors,
duplicate IDs and cancellation after an uncooperative embed or a typed cancellation.
Three host-inspector functions cover scoring/multiple matches, absent paths, stale
run IDs and malformed/partial reports. CI runs these without a phone or network.
Decision 0009 completes the M3-04 benchmark using the subsequent full independent
comparison. Integration (M3-11), calibration (M3-07), scale/resources (M3-08/M6-05)
and real-PDF acceptance (M3-10) remain separate; this fixture run does not pass them.

Full verification also passes: warning-free package build, 635 main Swift test
functions, the network-disabled suite, existing examples, six new probe functions,
53 Python tests, strict formatting/layering and DocC. Core/Runtime coverage remains
98.80% (2634/2666), unchanged from the preceding run; neither source target changed.
The app builds signed for the physical device with no team identity committed.

The opt-in unquantized MiniLM Core AI mode subsequently completed all 44 tensor
comparisons on the physical iPhone / iOS 27.2, with independently recomputed maximum
absolute error about 1.79e-7 against PyTorch (fixed tolerance 1e-4). See the Core AI
guide for artifact transfer, raw-parity checks and the pretokenized-fixture limits.
This is separate from the earlier NaturalLanguage asset run and four-bit MLX results.
