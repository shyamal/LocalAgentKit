# Receipt photo acceptance (M4-11)

The updated demo provides **Receipt expense** beside **Ask a PDF**. On iPhone,
choose a photo, select an image file, scan a receipt with the document camera, or try the bundled
synthetic receipt. macOS supports photo/file selection and the sample. The camera
usage description is in project.yml and the generated project. VisionKit document camera, UIKit rendering and picker
APIs were checked against the installed UIKit/PhotosUI interfaces and both app
platforms compile with Swift 6 strict concurrency.

## Flow and limits

1. Native accurate Vision OCR reads the authorized image. No model generation is
   used. Admission is 16 MiB encoded data, the provider's image/pixel bounds, 100
   OCR observations/12,000 recognized characters and 64 KiB UTF-8 recognized text.
2. OCR observations are grouped by vertical position and ordered left-to-right
   so labels and amounts in separate columns can be read as one row. The first
   row suggests the merchant. TOTAL/GRAND TOTAL/NET TOTAL/AMOUNT DUE labels can
   use an amount on the same row or nearby following lines, with supported
   grouping/decimal separators and currency markers. Conflicting totals remain
   blank; item counts, Subtotal, negative totals and malformed numbers are excluded.
   Dates support ISO/year-first slash/dot, unambiguous numeric day/month orders
   and English month names. Two-digit years map to 2000–2099 and require review;
   ambiguous numeric orders or conflicting dates remain blank. Explicit supported
   ISO currency codes suggest currency; `$` and `Rs.` do not select one.
   The saved date is always ISO and the total has two decimal places.
3. Review the preview and recognized text, and edit every field as needed. This
   narrow demo supports USD/EUR/GBP/LKR, totals from 0.01 through 1,000,000.00,
   two-decimal integer minor units, a valid ISO date and a merchant up to 160
   characters/640 UTF-8 bytes. It does not extract line items or reconcile tax.
4. Review and save snapshots an immutable record. A preselected AgentRuntime
   workflow passes its reviewed JSON through the M4-08 input binding to the
   user-confirmation-tier expense tool. The alert shows the immutable merchant,
   date and formatted amount from that pending record. **Nothing is written until
   that specific runtime request is approved.** Denial and pending-approval
   cancellation write nothing. A synchronous commit already in progress cannot
   be rolled back by subsequent cancellation.
5. The approved record appears with a checkmark and in Saved expenses. Reopening
   the sheet loads app-owned `Application Support/LocalAgentDemo/expenses.json`.
   The photo, raw OCR and chat conversation are not saved by this flow. Repeated
   calls with the same record UUID/content are idempotent; importing and approving
   the same receipt again creates a distinct record, not semantic deduplication.

The file store is actor-serialized, atomic, capped at 1,000 records/1 MiB, and
validates existing data before append. Corrupt storage fails closed and is not
replaced. All writers in the demo share its singleton; independent processes or
store instances writing the same file concurrently are not supported.

Camera encoding and photo-library transfer can allocate memory before encoded
size checks; these bounds do not guarantee a whole-process peak. Cloud photo/file
providers may download a chosen image. The host picker is outside the agent's
network-policy declaration. No full photo-library access or asset installation
is requested. Receipt text stays untrusted data, including text resembling tool
instructions; host review and runtime permission enforcement remain the boundary.

## Reproducible sample and automated acceptance

`Resources/receipt-sample.png` is generated by
`Scripts/make-receipt-fixture.swift` and contains no personal data. Expected fields:
LOCAL DEMO CAFE; 2026-11-16; 1250.50 LKR. The sample date is fixed, not today's date.
Regenerate from the repo root:

```bash
swift Examples/LocalAgentDemo/Scripts/make-receipt-fixture.swift \
  Examples/LocalAgentDemo/LocalAgentDemo/Resources/receipt-sample.png
```

Eleven new test functions cover conservative proposals, exact money and invalid
fields, approval/denial, reopen, idempotence/corruption, pending cancellation,
late OCR replacement, empty images and immutable review. The gated native function
runs the actual bundled image through Vision OCR, the reviewed runtime workflow,
permission approval and a temporary durable store. It passed on the Mac with
zero model generation calls. No production app record was written by that test.

```bash
swift test --package-path Examples/LocalAgentDemo
LOCALAGENTKIT_DEVICE_TESTS=1 swift test --package-path Examples/LocalAgentDemo --filter ReceiptNativeTests
```

Portable demo checks register 37 functions, including gated native cases. A Python
packaging regression also verifies the sample image is in the generated app's
resource phase; reading the fixture from source in host tests alone is insufficient.
A signed iPhone build was installed and launched with the sample loaded, without
automatic approval or saving:

```bash
xcrun devicectl device process launch --device <device-id> --terminate-existing \
  --environment-variables '{"LOCALAGENTKIT_RECEIPT_DEMO":"1","LOCALAGENTKIT_RECEIPT_SAMPLE":"1"}' \
  dev.localagentkit.demo.app
```

These developer-only launch variables open the receipt sheet and read the sample.
Normal launches retain the existing chat/PDF demo and do not load a photo.

## Physical acceptance

The user confirmed the corrected sample's date/amount fields appeared and approved
saving worked on the iPhone. A first real camera attempt recognized the shop but
missed date/price text. Capture was changed to the system document scanner, with
single-page crop/straightening and upright high-quality encoding. The user then
confirmed the scanned date/total were filled, approved the real receipt save,
and confirmed its row remained after closing/reopening Receipt expense. File-presence metadata confirms expenses.json exists;
no device expense contents were exported. Initial sample loading failed because
the PNG was absent from the generated app resource phase; that packaging issue
and its regression guard are fixed.

Additional manual regression coverage (not all exercised on this device):

- Relaunch the entire app and check saved history.
- Try other local photos, orientations, lighting and receipt layouts.
- Decline saving and confirm no new record; cancel OCR/pending approval and try
  another image. Try a blank/invalid image and camera denial with picker fallback.

Native scripted acceptance does not certify receipt accuracy or physical camera
behavior. The scanned-receipt → reviewed fields → approved durable row path is user-confirmed
on the device. OCR accuracy for other receipts and the additional manual cases
above are not established by this one successful flow.
