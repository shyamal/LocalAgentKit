# 0003: FR-026 and FR-027 — capabilities stay in v0.1, model-driven planning defers to v0.5

**Status:** Accepted, 2026-09-26 — this is P0-17
**Relates to:** PRD FR-026, FR-027, R1; decision 0002 (P0-15); tasks M1-RT-11, M1-RT-16, M1-RT-17, M5-01, M5-02, M5-03

## Context

FR-026 (Planning) and FR-027 (Replanning) each carry the same gate:

> **Gate:** this requirement ships as MVP-blocking only if the Phase 0 feasibility spike shows the on-device model can produce valid multi-step plans at an acceptable reliability rate. If not, the planner ships as a deterministic state machine that calls the model for individual step decisions, with model-driven end-to-end planning deferred to a later release.

Phase 0 measured 14% multi-step completion as shipped on both hosts, and 28% (macOS) / 20% (iOS) with each OS's framework bug worked around, against the >95% M5 bar (findings §12). Decision 0002 made `StateMachinePlanner` the v0.1 default on that basis.

**The subtlety this decision exists to resolve.** FR-026 is not one thing. It lists *capabilities* — sequential tasks, conditional tasks, tool dependencies, retries, completion detection — and also an *implementation*, the model producing the plan. The gate defers the implementation. Deferring the capabilities too would leave v0.1 with a state-machine planner that cannot sequence, branch, retry or decide it is finished, which is not a planner at all and contradicts decision 0002. `TASKS.md` had FR-026 wholly in Milestone 5 (M5-01), which reads that way; this decision corrects it.

## Decision

**FR-026 and FR-027 are MVP-blocking as capabilities, implemented deterministically. Model-driven planning and replanning are deferred to v0.5.**

**In v0.1 (Milestone 1), implemented in code by `StateMachinePlanner`:**

| FR-026 capability | How |
|---|---|
| Sequential tasks | The state machine's own control flow |
| Tool dependencies | Values flow through `AgentContext`; a step runs when its inputs exist |
| Conditional tasks | **Guards evaluated in code.** The model acted on a goal's verb and ignored its condition in 4 of 5 runs (findings §12, ms-10) |
| Retries | Bounded, with schema feedback (M1-RT-08), because single-call accuracy is 51–63% (§11) |
| Completion detection | The planner decides; the model may be *consulted* per step, and its answer is validated |

From FR-027, v0.1 ships **deterministic recovery**: a step whose tool returns nothing, or returns something that fails its own validation, takes a declared alternative path or fails with a typed error. That is the bounded, testable half of replanning — the "search notes, and if empty search documents" shape the model itself managed only 3/5 and 1/5 of the time (§12, ms-08).

**Deferred to v0.5 (Milestone 5):**
- The model emitting a whole plan (`ModelDrivenPlanner` driving the loop end to end).
- The model revising a plan from unexpected observations — open-ended replanning.

`ModelDrivenPlanner` still **ships in v0.1** as a selectable configuration (M1-RT-12); it is simply not the default and not the supported path. Promotion is gated by M5-03: re-run the P0-09/P0-10 suites against the then-current model, per OS version, and clear the >95% bar.

## Consequences

- **v0.1 can still do the PRD's example.** "Prepare me for tomorrow's meetings" runs as a deterministic sequence that consults the model per step. What it cannot do is invent a novel plan shape at run time.
- **Docs must not over-promise.** README and DocC should describe v0.1 planning as deterministic with per-step model decisions, and say plainly that end-to-end model planning is experimental and off by default. Phase 0's numbers are the reason, and they are public in `docs/phase-0-findings.md`.
- **`TASKS.md` is corrected:** M5-01/M5-02 are now explicitly the *model-driven* halves; the deterministic capabilities become M1-RT-16 and M1-RT-17 in Milestone 1.
- **This is reversible in one direction only.** If M5-03 later clears the bar, the default flips with a config change (the point of §2.4's two-planner design). Nothing in v0.1 needs rewriting for that.
- **Unaffected:** FR-028 (loop detection) and the four execution limits stay v0.1 as written; they are what make a bounded loop safe regardless of which planner drives it.

## Implementation note — 2026-11-02

M1-RT-12 provides the selectable experimental surface as model-proposed **linear
sequences**, compiled into existing workflows. The model selects tool order and
step instructions before execution; argument generation still occurs per tool.
Model-generated conditions, binding expressions, branching and open-ended
replanning remain deferred. This bounded subset does not complete M5-01/M5-02 or
change the default or its measurement gate. Its tests use mocks; reliability of
the real model in this configuration has not been measured.
